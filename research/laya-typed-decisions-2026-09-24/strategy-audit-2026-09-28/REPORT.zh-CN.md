# LightJev 实验复盘与方向建议

审计日期：2026-09-28。代码基线：`7434a3c`，另有此前初始化消融的未提交文件。

本次复查了训练代码、数据转换、逐条预测、训练清单和统计结果，只新增审计脚本、证据与本报告；没有修改训练实现、启动训练或重新读取官方公开测试集进行推理。

## 结论

目前的研究流程已经出现低效循环：在同一小组工作流上不断更换初始化、损失与随机种子，缺少先诊断失败机制、再决定实验的约束。工程交付有价值，但已有证据不足以判断模型能力到了上限，也不足以宣布某种底座或 RLCD 路线失败。

优先级应改为：**修复输入与目标函数的正确性 → 验证模型是否使用状态和判定标准 → 扩大任务与规则的覆盖 → 最后扩展训练和统计重复。**

这轮审计发现两个能够复现的实现问题。它们足以要求重建可信基线，但修复后能提高多少，仍须实验回答。

## 1. 先把不同实验分开

| 实验 | 准确率 | 能支持的结论 |
|---|---:|---|
| v0.1，NanoJev 合成任务硬标签测试 | 79.57% | 特定合成任务上的交付结果 |
| v0.2，typed-decisions 公开测试 | 78.60% | 已见工作流中的专项适配结果 |
| 独立候选评分，留出整个工作流 | 43.7% | 早期跨工作流基线，2 个种子 |
| 共享上下文，留出整个工作流 | 45.7% | 相应协议下的跨工作流结果，4 个种子 |
| 后续匹配 CE 实验 | 46.175% | 当前初始化与评分方式下的基线 |
| 匹配 CE + RLCD 实验 | 46.550% | 比 CE 高 0.375 个百分点，差异不确定 |
| 原始 Qwen 初始化的 CE 实验 | 42.358% | 这套直接迁移训练配方低于 v0.1 初始化 |

前两行和后面几行不是同一条学习曲线。共享上下文的早期实验与后续 CE 实验，开发集选 checkpoint 的候选排列处理也有变化，不能把所有增减都归因于单一因素。

匹配 RLCD 相对 CE 的种子与案例双重 bootstrap 95% 区间是 **[-1.74, +2.35] 个百分点**；NLL、Brier 还略差。这支持“当前实验未验证稳定收益”。下述实现问题进一步限制了对 RLCD 方法本身的解释。

原始 Qwen 初始化相对 v0.1 初始化下降 **3.817 个百分点**，对应区间约 **[-6.20, -1.45]**。这是实际负结果，应该保留；但旧模型已有决策任务训练和成熟的评分头，新模型采用随机评分头、没有专门的头部预热，沿用同样的 256 步迁移预算。它没有排除更合理的 Qwen 训练配方。

## 2. 已证实的实现问题

### 2.1 布尔题丢失判定标准

`workflow-generalization/prepare_lightjev_records.py:19–20` 对 NOUL 题只生成 `false`、`true`，没有保留对应的 `criteria`；第 41 行的问题文本也仅包含 `instructions`。Choice 和 Score 则包含选项标准。

审计官方 train 分区的 1,200 个案例、6,000 个决策：**1,200 个决策带有布尔判定标准，转换后全部丢失，占全部决策的 20%。** 涉及四个模板：

- `agent_trace_observability / needs_review`
- `customer_service / needs_human`
- `invoice_processing / matches_order`
- `security_incidents / true_positive`

例如“是否需要人工处理”本来提供了自动化可处理与需要人工判断、权限或共情之间的具体界限。只保留题目与真假标签，改变了模型接收到的任务定义。

Laya 路径将 `crit` 传入其选项渲染器，并保留 NOUL 的标准。因此双方收到的信息不同。旧 LightJev 结果仍是旧协议下的真实结果；同一缺陷下各 LightJev 实验之间的差异仍有条件性参考价值，但不能直接用于判断与 Laya 的能力差距。

修复时需要同步处理数据契约、训练和推理。布尔候选若必须严格为 `false/true`，可将两侧标准明确编码进问题上下文，不能只改一个转换器而造成训练与推理不一致。

### 2.2 等级奖励使用了打乱后的顺序

`train_lightjev_shared_fold.py:17–27` 会随机打乱候选与目标。`rlcd_ce_loss:66–70` 又直接按这个排列计算累计概率的 RPS，未恢复等级的语义顺序。该逻辑也存在于历史实验代码中。

CE 和球面评分可以随候选一起重排；等级的累计概率评分不能这样处理。一个直接反例：

| 正确等级为 0 | 按等级 0、1、2 计算 RPS | 按展示顺序 0、2、1 计算 RPS |
|---|---:|---:|
| 预测等级 1，错一级 | 0.5 | 1.0 |
| 预测等级 2，错两级 | 1.0 | 0.5 |

惩罚次序被颠倒了。Score 占该数据 40% 的决策；具体排列对奖励的影响不同，不能解释成每个 Score 样本都受同等影响。

修复方式是明确分离“展示顺序”和“语义等级”，计算 RPS 前恢复等级顺序。必须加入“只改变展示顺序，RPS 不变”和“相同条件下远距离错误惩罚更大”的回归测试。已有测试只验证有限梯度、CE 和参数检查，没有覆盖这一语义性质。

## 3. 结构问题：共享文本并不等于公平地看到全部选项

`shared_context.py:44–49` 在每个候选后立即放置评分位置，再从各位置的隐藏状态取分数。Qwen 使用因果注意力，早面的评分位置看不到后面的候选标准；后面的评分位置能看到前面的候选。

随机打乱和多次排列平均可以缓解位置偏差，但不能让一次前向中的每个评分位置都看到全部候选。Laya 的双向编码器和候选交互结构没有这一因果可见性限制。

这是确定的结构性质，**它造成了多少准确率损失尚未证实**。下一轮应先测排列、候选重命名与判定标准反事实的影响。

一个值得小规模验证的 Qwen 基线：先完整读入状态、问题和全部候选标准，在最后一个位置用预训练语言模型头给候选编号打分，再对这些编号的 logits 做归一化和 soft-target CE。需要验证编号的 tokenization，并处理编号映射与位置偏差。这样既保留成熟输出头，又保证评分时看到全部选项；其优势仍需实验验证。

## 4. 数据与选型方式限制了研究进展

### 4.1 任务覆盖远小于决策条数

官方训练分区只有 **4 种工作流、20 个问题模板**。每个案例有 5 个相关决策，6,000 行决策不等于 6,000 个独立任务。

每个留一工作流实验，用其他三类中的 816 个案例训练，42 个案例选择 checkpoint、42 个案例校准；开发集仍来自训练工作流。源域 NLL 最好的模型，未必是跨领域最好的一步。

增加随机种子提高了对训练波动的估计精度，不会增加领域覆盖。现有案例与种子区间也不能表达“随机抽一个全新行业”的不确定性。

更关键的是，多轮根据同样四个留出工作流的结果决定下一种配方后，它们已经承担研究开发集的功能。没有梯度泄漏，也仍然存在对评测结果的适应。后续需要新增且冻结的任务家族测试集。

### 4.2 先诊断输出偏向

从 CE 的逐条预测重新统计，四个种子合计的结果如下；每行有 300 个独立案例、1,200 次重复预测。

| 留出域 / 问题 | 模型行为 | 对应真实标签比例 |
|---|---|---:|
| 发票 / disposition | 94.83% 预测 approve | 40.00% |
| 发票 / urgency | 90.33% 预测等级 1 | 43.67% |
| 安全事件 / credential_compromise | 90.25% 预测 true | 56.00% |

这提示需要优先调查默认答案偏向、是否依赖状态、是否理解判定标准。仅凭这些统计，还不能把原因确定为某一个机制。

低准确率也不能主要归咎于软标签含糊：目标前两项概率差小于 0.1 的决策占 12.73%；在差值至少 0.1 的样本上，CE 准确率仍只有 47.48%。54 个硬标签与首个 argmax 不一致的样本均属于数值容差内的并列，没有据此发现非并列标签矛盾。

### 4.3 尚未证明“多训导致过拟合”

16 个 CE 实验中，11 个最佳开发集 checkpoint 在最后的第 256 步；16 个 RLCD 实验全部如此。现有记录不足以认定训练时长已导致开发集过拟合，也不支持直接断言继续加步数有效。

应该在新的开发任务家族上保存中间 checkpoint 的表现，区分优化尚未完成、源域适配与跨域遗忘，再决定步数。

### 4.4 RLCD 没有引入新监督信息

目前奖励来自已有软标签的 log score、球面分数和 RPS，没有额外环境反馈或新轨迹。随机扰动与策略梯度改变了优化方式，但没有增加监督信息。

这些分数可直接对预测概率求导。因此修复语义顺序后，应先比较 CE 与“CE + 直接可微的有序损失”。若简单基线仍无收益，应检查目标与数据，而不是立即扩大带采样的 RL 搜索。

## 5. 报告口径也需要修正

- **初始化来源：**发布清单表明 v0.2 的实际路径为 Qwen3 → LightJev v0.1 → typed-decisions CE，不能只写直接从 Qwen 初始化。
- **ECE 聚合：**CE 的 16 次实验 ECE 均值为 0.07956，合并 24,000 次预测后计算为 0.04126。这是两个不同统计量，不能混用。RLCD 对应为 0.07869 与 0.04149，连排序也可能变化。
- **不确定性：**bootstrap 中正差值的占比不能直接表述成方法更优的后验概率。
- **实验身份：**每个报告应固定数据协议、初始化、输入渲染、checkpoint 选择、校准、聚合方式与评估预算，修正协议后的成绩另列版本，保留旧负结果。

## 6. 下一阶段的具体方向

### 第一阶段：恢复可信基线

先完成布尔标准与等级顺序修复、端到端输入快照、语义回归测试以及文档来源修正。把旧协议留作历史记录，建立修正后的新协议。

同时增加廉价诊断：

1. 固定语义，只换候选展示顺序、无意义编号和记录 ID，检查预测变化。
2. 固定状态，改变业务判定标准，使正确决策必须改变，检查模型是否跟随。
3. 固定标准，只改决定结论的关键事实，检查模型是否跟随。
4. 用打乱状态、删除状态作为诊断对照，检查模型有多少收益来自真实案例信息；不把缺失输入当正常任务评测。
5. 按问题模板列混淆矩阵、预测分布和错误实例，优先解释 approve 等极端偏向。

诊断在开发数据上迭代。输入正确性没有通过前，不启动新的 16 组训练矩阵。

### 第二阶段：用小实验选择建模方向

建议按顺序比较，而不是同时改变所有组件：

| 顺序 | 对照 | 回答的问题 |
|---|---|---|
| A | 旧 CE 与修正输入后的 CE | 输入遗漏影响多大？ |
| B | 修正后的 CE 与 CE + 直接可微 RPS | 有序目标是否提供增益？ |
| C | 相同完整输入下，当前评分结构与 Qwen 最后位置候选 logits | 因果可见性与输出头是否限制了迁移？ |
| D | 在同等任务信息、明确初始化来源下，与 Laya 对照 | 我们是否有值得保留的效果、效率或可控性优势？ |

先用 1–2 个种子和少量开发任务筛查，只有机制诊断通过、效果值得继续的方案才扩展到多种子验证。若重做原始 Qwen 初始化，加入头部预热或保留语言模型头等合理方案，并报告全部训练成本。

建议事先约定一个有工程意义的增益门槛，例如开发任务平均提高 2 个百分点，同时源域、校准和关键错误类型不过度退化。这只是可商定的资源门槛，不是统计定律。最终证据仍需要冻结后的主指标、独立任务家族、多种子与相应不确定性分析。

8 张卡适合并行运行有明确区分能力的对照。共享上下文、CE、RLCD 三组已有 48 次运行，清单累计约 40.1 个单卡小时；下一轮的重点应是每项实验能排除什么解释。

### 第三阶段：把核心投入转向任务与规则泛化

建议将下一版明确定位为：**根据用户给出的判定标准，在未见过的工作流中做受约束决策的模型。** v0.2 保留为专项模型，避免把现有专项成绩当通用能力。

数据建设可先以 20 个以上独立工作流家族、5 个以上冻结测试家族作为起点；这些数量是建设建议，不是充分泛化的保证。

- 按任务家族、政策规则和生成机制划分数据，不把改写同一模板当跨领域测试。
- 构建同一状态、不同规则的成对样本，以及同一规则、关键事实改变的成对样本。
- 补足困难负例和少数决策，避免模型靠默认 approve/true/低等级得到局部收益。
- 可执行规则提供可验证标签；开放判断使用独立审查和教师分歧抽检，避免只学单一教师偏好。
- 旧四工作流作为辅助回归集，新冻结家族用于最终结论。显式报告按家族的结果，不只给决策行的总平均。

若完整输入、合理评分结构和更广数据仍显示 Qwen 路线没有优势，就切换到适合双向候选比较的编码器或 Laya 派生路线。Qwen3-0.6B 是候选方案，不应成为必须证明成功的前提；目前也没有充分证据要求立刻放弃它。

## 7. 对此前推进方式的修正

此前将一次初始化消融扩大成底座方向的失败判断、用有缺陷的奖励实现解释 RLCD 是否有效，都过于肯定。重复运行和完整日志有助于审计，但不能替代对输入、目标和失败机制的检查。

判断是否走出循环的标准应是：下一轮能解释哪些错误减少、为什么减少、是否迁移到新规则与新任务，以及代价是多少。若只是同一批题上的均分上下波动，即使再训练一轮，也没有解决方向问题。

本报告给出的是审计和下一阶段建议，所述修复与新实验尚未执行。
